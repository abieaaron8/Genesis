# Root Cause Report: Supporting Evidence Classified as Contradicting

## Scope

This audit covers only the verification pipeline after retrieval for:

> The sunshade for NASA's Near-Earth Object (NEO) Surveyor mission has completed preparation for flight testing.

No UI code or retrieval implementation was changed.

## Executive finding

Evidence retrieval is working. The retrieved sources are NASA and NASA-affiliated sources with high relevance and credibility. The primary logic bug occurs after retrieval:

1. The deterministic prosecutor finds no actual contradiction.
2. Instead of returning no contradictory arguments, it calls `_minimal_opposing_arguments(...)`.
3. That helper creates caveat arguments for the first three retrieved articles and labels them as `stance: "challenges"`.
4. `backend/main.py` interprets every prosecutor argument as an explicit contradiction and writes `CONTRADICTS` onto the matching evidence rows.
5. The evidence partition then counts those rows as contradictory.

The exact stance corruption occurs at:

```text
backend/main.py:802
_apply((prosecutor_result or {}).get("arguments"), "CONTRADICTS")
```

The incorrect arguments originate at:

```text
backend/agents/prosecutor.py:158-160
arguments = _minimal_opposing_arguments(claim, evidence)
```

This is not a reversed retrieval score, a similarity-threshold failure, or a swapped prosecutor/defender function call. It is a semantic mismatch: a caveat/uncertainty argument is later treated as proof that the source contradicts the claim.

## Exact post-retrieval flow

### 1. Retrieved rows enter the agents

`backend/agents.py:448-480` passes the complete retrieved evidence list to `run_prosecutor`.

`backend/agents.py:537-569` passes the same evidence list to `run_defender`.

There is no prosecutor/defender argument swap at this stage.

### 2. Prosecutor creates false contradiction metadata

`backend/agents/prosecutor.py:101-115` defines the prosecutor as an agent that finds evidence against the claim.

`backend/agents/prosecutor.py:156-160` runs the deterministic path:

```python
arguments = _deterministic_arguments(claim, evidence)
if not arguments:
    arguments = _minimal_opposing_arguments(claim, evidence)
```

For this NASA claim, `_deterministic_arguments` finds no `CONTRADICTS` source. The fallback nevertheless creates three arguments from `evidence[:3]`.

`backend/agents/prosecutor.py:16-46` labels those entries as:

```python
"stance": "challenges",
"minimal": True
```

They are caveats, not source-level contradictions.

### 3. Defender correctly identifies supporting evidence

`backend/agents/defender.py:100-116` defines the defender as finding evidence for the claim.

`backend/agents/defender.py:155-160` uses the deterministic classifier and, for this run, produces supporting arguments. The observed defender output contains five `supports` arguments and `defense_strength = "strong"`.

### 4. Agent arguments overwrite source stances

`backend/main.py:750-802` reconciles agent arguments back onto the evidence rows.

The key code is:

```python
_apply((defender_result or {}).get("arguments"), "SUPPORTS")
_apply((prosecutor_result or {}).get("arguments"), "CONTRADICTS")
```

The defender is applied first, but the prosecutor is applied second. If both agents cite the same source, the prosecutor assignment wins.

For this claim, the prosecutor’s first three caveat arguments match the first three NASA rows by title/source. The code then writes:

```python
row["stance"] = "CONTRADICTS"
```

This is the exact point where supporting NASA evidence becomes contradiction evidence in the main response.

### 5. Partition counts the overwritten rows as contradictory

`backend/main.py:835-852` runs `_partition_sources_by_stance`.

At `backend/main.py:848-850`:

```python
if stance == "CONTRADICTS":
    contradictory.append(row)
```

The partition does not distinguish:

- an actual source contradiction,
- a prosecutor caveat,
- a minimal uncertainty argument.

As a result, the overwritten rows become contradictory evidence.

### 6. Side-extension can amplify the wrong side

`backend/main.py:1971-1984` calls `_extend_side_rows` for both sides.

`backend/main.py:1337-1388` adds rows to a side based on heuristic stance scores. For the prosecutor side, it accepts rows when:

```python
margin = contradict_score - support_score
if margin > 0:
```

This is a secondary amplification mechanism. It can add rows to the prosecutor side based on lexical cues, even when no agent explicitly marked the source as contradictory. It does not create the primary three false contradictions in this trace; those already exist because of the prosecutor fallback and reconciliation overwrite.

### 7. Judge receives equal strong sides

The observed deterministic judge input was:

```text
prosecutor_strength = strong
defender_strength = strong
p = 3
d = 3
```

This comes from `backend/agents/judge.py:200-205`, where strengths are converted through:

```python
STRENGTH = {"strong": 3, "moderate": 2, "weak": 1, "none": 0}
```

The judge output then follows `backend/agents/judge.py:253-260`:

```text
verdict = MISLEADING
confidence = 62
```

The judge’s “both sides are equally strong” result is a downstream consequence of the prosecutor fallback being counted as real contradiction evidence.

## Bug ranking

### 1. Critical: caveats are converted into `CONTRADICTS`

**Files and lines**

- `backend/agents/prosecutor.py:156-160`
- `backend/agents/prosecutor.py:16-46`
- `backend/main.py:799-802`

**Impact**

Sources that support the claim are relabeled as contradictory merely because the prosecutor creates minimal uncertainty arguments for them.

### 2. High: prosecutor overwrite wins when both agents cite one source

**File and lines**

- `backend/main.py:799-802`

The code intentionally applies the prosecutor second so explicit contradictions win. However, because minimal prosecutor caveats are incorrectly represented as source contradictions, this precedence rule turns a false caveat into the final source stance.

### 3. Medium: side-extension uses lexical score margins as stance

**File and lines**

- `backend/main.py:1337-1388`
- `backend/main.py:1372-1375`

This can add sources to the prosecutor side without an explicit contradiction from the source or an agent. It amplifies classification errors but was not the original cause of the NASA rows becoming contradictory.

### 4. Medium: count-based judge aggregation treats argument strength as contradiction strength

**File and lines**

- `backend/agents/prosecutor.py:88-99`
- `backend/agents/judge.py:200-260`

Minimal caveat arguments receive ordinary strength scoring. Three high-credibility NASA rows therefore produce `prosecution_strength = "strong"`, even though none contradicts the claim.

## What was not the cause

- Retrieval returned relevant NASA sources.
- Credibility scores were high: `0.94` for the primary NASA sources.
- Relevance scores were `1.0`.
- No prosecutor/defender function call swap was found.
- No reversed similarity comparison was found in the observed path.
- No support/contradict label inversion exists in `_partition_sources_by_stance`; it correctly partitions the stance value it receives.
- The final `MISLEADING` result is consistent with the corrupted inputs supplied to the judge.

## Final conclusion

The single root cause is the prosecutor’s “minimal opposing analysis” fallback. It converts the absence of a contradiction into synthetic caveat arguments, and `backend/main.py:802` then promotes those caveats to explicit `CONTRADICTS` source labels. The evidence is not being retrieved incorrectly; it is being relabeled incorrectly during agent-to-evidence reconciliation.

The exact correction point is the contract between:

```text
backend/agents/prosecutor.py:_minimal_opposing_arguments
```

and:

```text
backend/main.py:_reconcile_stance_from_agents
```

The pipeline must keep “challenge/caveat/uncertainty” separate from `CONTRADICTS`. No UI or retrieval change is required.

## Remediation applied

The unsafe `_reconcile_stance_from_agents` bridge was removed from
`backend/main.py`. Prosecutor and defender arguments are now analysis-only:

- They are not matched back to retrieved rows.
- They cannot overwrite `row["stance"]`.
- They cannot contribute directly to `supporting_sources` or
  `contradicting_sources`.
- Source counts are computed only from retrieved/curated evidence rows after
  `_partition_sources_by_stance`.

The NASA claim was retested after the change. The response contained:

```text
supporting_sources = 4
contradicting_sources = 0
evidence rows with CONTRADICTS stance = 0
```

The prosecutor still returned three `challenges` arguments for its separate
analysis panel, but those generated arguments no longer changed evidence
stances or source counts. All affected backend modules compile successfully.
